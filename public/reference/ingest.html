OBX Ingest API (write side) (0.1.0)

Download OpenAPI specification:

URL: https://openbrandexchange.com License: CC-BY-4.0

How a brand's own systems publish content to any OBX node.

Normative. The OBX Ingest API lets a brand's automation (PIM/ERP/DAM connector, spreadsheet export, the obx CLI, a GitHub Action, n8n/Make/Zapier) publish to ANY conforming node. It is keyed by the brand's own ids, so every write is an idempotent upsert: send the same thing twice and nothing changes (and no change entry is written).

See docs/ingest.md for the full semantics, including exactly how writes appear in the OBX Protocol /changes feed, and docs/import-format.md for the canonical CSV and image filename pattern.

Authentication: Authorization: Bearer <ingest token> (tokens start with obxi_), created in the node admin. Scopes: ingest:read, ingest:write, ingest:delete. A token MAY be restricted to some brands; writes outside them fail with 403 forbidden.

Errors are application/problem+json with obx_error (see docs/protocol.md#errors). Unknown fields in request bodies MUST be ignored by nodes (forward compatibility) and reported as a warning in the result.

Create or replace asset metadata

The product MUST exist (unknown_parent). position MUST be free among the product's other non-deleted assets of the same color_code (409 position_conflict; replacing an image = reuse its external_id). files attaches blobs uploaded earlier (422 blob_missing if a sha256 is unknown); this is the atomic way to replace an original together with client-generated renditions. The asset becomes visible once its original and all required renditions exist (visibility: pending_files until then).

Upload the original or a client-generated rendition

Raw body, Content-Type of the file. OBX-Content-SHA256 is RECOMMENDED; when present the node verifies it (422 checksum_mismatch). The asset metadata MUST exist (404). Uploading the same bytes again is a no-op (unchanged).

Replacing original on a node without server-side renditions: the node keeps serving the previous original and renditions until all required renditions uploaded AFTER the new original are present, then swaps atomically (one asset upsert in /changes). Renditions MUST follow the rendition rules (web/thumb: JPEG, longest side <= 2000/600, never upscaled; square: web on a white square canvas); nodes MAY reject (422 validation_failed) renditions whose size violates them.
